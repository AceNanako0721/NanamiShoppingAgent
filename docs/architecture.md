# Architecture

The host owns reasoning and interpretation. The MCP process exposes bounded domain tools; it has no sampling, elicitation, model credentials, shell, eval or arbitrary browser actions. `contract.py` owns versioned schemas, `service.py` orchestration, `domain.py` exact arithmetic, `store.py` durable invariants, and adapters execute explicit read or synthetic operations. MCP transport is independent of that business core.

The trusted local operator creates immutable budgets and purchase targets, assigns principals to targets and records sourced FX observations. The process config binds principal and namespace outside tool arguments. A task ID is an opaque reference, not an authorization credential. Every object read checks both namespace and task ACL. Separate authorized stdio processes share one SQLite file; `BEGIN IMMEDIATE`, uniqueness constraints and FULL synchronous commits serialize claims across threads and processes.

The operator's stable goal key is unique within a namespace. Its target ID persists across every URL, candidate, platform, seller, label and quote. The model cannot mint another target through MCP. The operator must never create a replacement goal to work around an unresolved purchase. Shared budgets are cumulative spending envelopes: completed spending and uncertain reservations remain charged. There is intentionally no model-facing release/reset mechanism.

Quotes include seller, SKU, variant, condition, original currency, payable breakdown, quantity, destination/payment opaque references, expiry, target budget and constraints. Synthetic grants hash the entire exact quote, not a caller-supplied approval boolean. Grant issuance is a trusted test operator action, outside MCP. Real owner identity/approval integration does not exist in this release.

Read-only search batches run concurrently inside an ordinary executor and return persisted references. Completed identical searches reuse stored results; there is no autonomous agent loop or durable background worker daemon. A process killed during a read can leave `searching`; an explicit read request may safely resume it. A disconnected host never triggers an automatic write retry. Cached search evidence remains timestamped and may be stale; preview and final review re-read the synthetic merchant. Public search cache refresh and a durable read-job scheduler are future enhancements.

Before browser checkout, a single atomic transaction checks the exact grant and expiration, target cap and shared cap, inserts the target claim and reserves the full payable. Only then may the synthetic browser open checkout, recheck all quote fields and expiry, and perform its sole hardcoded final action. An exception after claim always keeps a conservative uncertain lock and reservation, even if evidence suggests no click occurred. This intentionally requires operator review rather than guessing that a retry is safe.

Receipts must come from the configured synthetic origin, match task ID, complete quote hash, amount, currency, quantity, SKU, variant, seller and condition. They are read from the merchant's durable store through the browser. Missing/mismatched receipts never complete or unlock a claim. Synthetic tests kill the complete worker process group after acceptance, restart independent MCP processes and reconcile without a second POST.

Public adapters use credential-free GET over TLS with a narrow host/path/query allowlist. DNS resolution rejects private and mixed answers; the connection is pinned to the validated public address with hostname TLS verification. Every redirect is checked before another request. No proxy environment, cookie jar, authenticated browser, private API or automatic retry is used. Public evidence stores bounded facts and hashes, not raw DOM. Listing titles and merchant JSON are untrusted data. Partial fields cannot authorize checkout or prove same SKU.

Synthetic browser requests are limited to one exact operator-configured numeric loopback origin and fixture paths/methods. Service workers, JavaScript, downloads and persistent profiles are disabled. No CDP endpoint is accepted. Test fixture state is synthetic and temporary.

Streamable HTTP is deferred. No HTTP listener, bearer credential, anonymous remote shopping path or claim of authenticated remote multi-client operation is included. Shipping/payment integrations, real owner grants, production multi-user isolation and real marketplace dispatch require independent design and verification.
